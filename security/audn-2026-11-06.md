## 重要邊界與相容性

### 不是所有報告項目都有相同攻擊前提

流量刪除、模型設定、同步、更新、批次匯入等管理端點需要有效認證。自訂工具及攔截規則的風險則位於「管理者授予 agent 的工具能力」與「模型／目標提供的輸入」之間。不能把所有項目都描述成未登入即可取得主機控制權。

自訂工具原本仍有 task RoE、egress 與攔截檢查；本次修補的是參數不能變成模板語法的根本邊界。JSON 規則缺口也不代表 norma 所有已解碼的安全檢查都失效。

### 部署行為變更

| 行為 | 修補後 |
|---|---|
| 登入頻率 | 每 TCP peer 每分鐘 10 次、單一管理帳號每分鐘總量 100 次；在同一反向代理後共享 peer 額度，不能用任意 `X-Forwarded-For` 取得新額度 |
| 自簽／無效憑證靶機 | 預設拒絕；只有明確 `ARTEX_PROXY_SSL_INSECURE=true` 或 `1` 保留相容模式 |
| SMTP | 隱式 TLS 或 STARTTLS；只有明確 `allow_insecure=true` 才允許無 STARTTLS 的中繼。變更此目的地安全設定也必須重新提供儲存憑證 |
| LLM／MCP 秘密 | 相同正規化目的地可保留；更換 provider、URL、proxy 後需明確提供相應秘密。跨來源 redirect 被拒絕 |
| stdio MCP | 依賴服務環境中的非必要變數時，必須在該 MCP 設定內明確提供 |
| Docker 安裝 | Docker／Compose 不存在就停止；不再執行即時下載的 shell 安裝腳本 |
| reset `.env` | 支援允許鍵的字面值與單／雙引號；不執行 shell、command substitution 或 Compose interpolation，複雜部署請以參數提供已解析值 |
| 資源上限 | 歷史頁 200 筆、資產匯入 2 MiB／1,000 筆、訊息 2 MiB／32 附件、同步 64 KiB／100 目標／3 類型、SSE 行與 event 8 MiB |
| 更新包 | 壓縮 ZIP 最多 1 GiB；已知 metadata 大小形成更小的上限；原有解壓後 binary 512 MiB 上限保留 |

這些選項是明確的相容性例外；啟用後仍承擔相應的明文或未驗證傳輸風險。

更新互斥涵蓋同一服務程序中的操作；不宣稱能協調多個獨立程序同時操作同一個 executable。流量 legacy 目錄沿用保留所有底線前綴的既有 store 規約；因此某些歷史 IPv6 名稱經 sanitize 後的 legacy 目錄會保留，資料列仍可刪除，不能為了清理它們而放寬內部儲存保護。

## 驗證方法與可重現性

### 原版確認

在獨立的 `17006d40` worktree，使用合成輸入重現：

- `null` 解碼得到 nil map；
- 大於 2 MiB 的資產 body 仍回 200；
- 超過 1,000 筆的資產 batch 進入逐項處理；
- 65,561-byte 的大量換行 SKILL.md 解析配置約 1,130,501 bytes，而修補後的測試要求額外配置不超過 4 KiB。

另外的回歸測試涵蓋模板參數隔離、JSON 等價表示、實際 SQL OR 優先序、domain/IP 正規化、內部儲存目錄、SSE 行／event 大小、取消、log fan-out、rollback、受控下載、憑證 redirect、MCP 子程序環境及 SMTP 降級。正常控制案例與錯誤案例並存；未實際執行破壞性 payload 或以 OOM 作為成功指標。

### 必要檢查

`.github/workflows/security-regressions.yml` 將所有 `*security*_test.go` 中的測試及既有 auth tests 納入獨立 gate，**任何未執行或 skip 都視為失敗**。PostgreSQL 必須指向拋棄式服務，測試使用獨立 schema 或既有隔離慣例。另執行並行路徑 race detector、全套 `go vet`／`go test`、前端認證／URL 測試與 TypeScript 檢查。

本機沒有 PostgreSQL 時的 PASS 不代表資料庫路徑已驗證；以此變更最終 commit 的 CI 結果為準。舊 PR 的綠色紀錄只證明當時已存在的修補，不能替代本次新增交易、profile 或 DSL 測試。
