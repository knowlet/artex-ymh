# 攔截審批：按需智慧審查

## 使用

在 **系統 → 攔截 → 模型配置** 可選啟用 **背景智慧審查**（需勾選資料外送同意）。啟用後，新進入 `pending` 的審批會由背景 worker 自動排程審查，無需手動點擊；UI 會自動輪詢顯示佇列／進行中／完成狀態。仍可在詳情內 **手動審查** 或 **停止自動重試**。手動與背景皆不變更核准結果。演示模式不呼叫模型。

沿用「攔截設定 → 裁判模型」選擇的 profile；未指定（ID 0）時使用當下的全域啟用 profile。明確指定的 profile 不存在或不可用時失敗，不另找其他模型。此功能沒有新增 Agent，也不使用執行 harness、工具清單或模型故障轉移鏈。自動兜底裁判的啟用開關不等於手動審查開關：停用兜底裁判仍可主動要求這次諮詢。

回應包括風險（低／中／高／極高／無法判定）、理由、成功後影響與人工檢查建議。**低風險或「可考慮核准」都不是授權**。人工核准／拒絕按鈕仍獨立運作，模型結果不會改變 `intercept_pending.status`、`decision_source`、`decided_at` 或喚醒執行者。

### 原有逾時與放行政策不變

審查不延長原審批期限，不暫停既有等待計時，也不修改一鍵放行或逾時放行設定。已設定的自動／逾時放行仍由既有流程處理；不能把本功能當成防止這些既有政策生效的安全邊界。模型本身最多使用 60 秒、最多 1536 個輸出 token。沿用 profile 的串流／非串流模式；實際傳輸層的重試受同一 deadline 限制。

## 資料與隱私邊界

模型收到本次儲存的工具名稱、原始參數、攔截理由、命中規則 ID、目前攔截規則與設定。任務內的請求另含該任務的範圍宣告和操作限制。範圍宣告不是外部授權的證明。

只有與本次動作相符的 v4 模型輸入快照中「明確選取的使用者背景」和工作目錄會轉送。舊版上下文、完整對話、Worker 排程提示、歷史執行輸出與之前的審查建議不會重新送入模型。沒有 v4 快照會標示背景不可用，不能推定腳本內容、目標環境或授權已查證。審查不讀取參數指定的檔案，也不測試任何命令。

不把 profile API key 或代理憑證加入審查輸入；但**原始命令、工具參數、選取背景及操作政策本身可能含敏感資料**。請依裁判模型的資料處理政策決定是否按下按鈕。輸入上限 64 KiB，單個政策項目 16 KiB，各集合最多 200 筆／32 KiB；超出直接拒絕，不截掉可能影響判斷的限制。

結果仍是不可信模型文字，介面以 React 文字節點呈現，不當作 HTML、Markdown、指令或設定執行。解析器拒絕重複／未知欄位、錯誤大小寫、額外 JSON、截斷、過長輸出、非法 UTF-8、工具呼叫與不完整串流。

## 保存、競態與限制

最新一次審查保存在既有 `intercept_pending.audit.approval_advisory`，沿用既有資料保存／刪除邊界，不新增資料表或額外 DDL。原審批 audit 欄位以 JSONB 合併保留，舊紀錄沒有執行快照的事實也保留。**這不是每次重試的完整歷史列表**；重新審查取代上一筆建議。一般審批列表不攜帶審查全文。

PostgreSQL row lock 僅用於短暫認領和保存，不涵蓋模型呼叫。每個審批最多一個未過期的審查租約；重複點擊回傳現有 running 狀態，成功且輸入指紋相同則重用結果。指紋包含動作、選取背景、規則／政策、模型設定版本與審查格式版本。

審查完成時重新比對快照。人工或原逾時流程已處置的審批、動作或政策改變，都不會被稍後到達的模型回應覆寫。舊租約不能覆寫新嘗試。失敗、逾時、取消或失效結果不保留可供放行的結論；由使用者明確重試。程序重啟後，已完成結果仍可讀取，進行中租約到期後才允許重新認領（模型 deadline 外加 30 秒清理寬限）。單一 HTTP handler 最多四個並行審查，不排無界佇列；跨程序只有同一審批的去重是全域的。

成功後政策再改變，或審批已結束，GET 會把結果標為歷史／非 current；此判斷只是 UI 快照，不是可轉用的授權票據。模型結果不保證正確，不能取代人工查證。

## API

`GET /api/intercept/pending/{id}/advisory`：已登入使用者讀取最新審查，無模型呼叫，`Cache-Control: no-store`。

`POST /api/intercept/pending/{id}/advisory`：空 body 或 `{}`，只能審查資料庫中的 pending 動作，不接受替換命令、prompt 或 model。沿用既有 Bearer 認證，無匿名或 SSE ticket 例外。

`POST /api/intercept/pending/{id}/advisory/cancel`：**停止自動重試**（`auto_cancelled`）。不會中斷已在進行中的模型 HTTP 呼叫；若取消發生在推理期間，完成的回應會在保存前丟棄，不會成為「目前建議」。手動審查與人工核准／拒絕不受影響。

**每日預算**僅計入成功**認領**後、**觸發=auto** 的審查次數（非金額上限）；`manual` 路徑不扣減。

`GET/PUT /api/intercept/advisory-auto`：背景審查開關、資料外送同意時間戳、全域並行上限、失敗重試與每日預算。啟用時必須提供 `consent_at`（RFC3339）。

回應 `advisory_only: true`、`approval_status`、`current`、`assessment`。`assessment.state` 為 `running`、`succeeded`、`failed` 或 `stale`，內部 lease ID 不對外輸出。

HTTP 200：已保存／重用結果（仍須檢查 state，200 不代表模型成功）；202：加入既有審查；400：錯誤請求；401：未認證；404：無紀錄；409：審批已結束或動作已改變；413：請求 body 太大；429：本服務審查容量已滿；503：無法取得模型／完整政策快照或保存結果。錯誤回應不包含原始模型／provider 錯誤。

## 驗證

新增測試使用固定假模型和隔離／明確 opt-in 的測試 PostgreSQL，不連真實 LLM，不執行被審查工具，不掃描外部目標。CI 對選取測試逐一要求 PASS，任何 SKIP、缺測或失敗皆不通過。

- `approvalreview`：嚴格 schema、重複欄位、UTF-8、大小與指紋。
- `db`：多連線單一租約、持久快取、人工決策、過期租約、舊回應、動作變更、原 audit 與舊紀錄缺失快照保留。
- `server`：實際 HTTP 路由／JWT、GET 不呼叫、手動重試與快取、重複點擊、人工決策競態、模型格式／工具／逾時失敗、敏感錯誤不外洩、scope／背景界線、取消與容量。
- `web/tests/approval-advisory.test.mjs`：結果與紀錄 ID／狀態一致性、已完成／失效建議、租約有界輪詢。另執行 TypeScript 型別檢查與正式靜態建置。
- 本機瀏覽器 E2E（`scripts/e2e-advisory.sh`，Playwright + 拋棄式 PG + `advisoryFake`）：驗證審批列表、背景自動狀態文案與取消標籤；不跑真實 LLM。

這些自動測試不等於真實 provider 行為、多 replica 壓力或正式部署已驗收；發布時應另外檢查實際 UI、反向代理逾時及既有審批計時設定。

### 本機 E2E 與簽名金鑰 hygiene

- Playwright harness 僅使用記憶體內測試用 JWT 材料（與 `auth_test.go` 同源常數）及 `t.TempDir()` 資料目錄；**不得**在 repo 內留下 `server/jwt.key`。
- `scripts/check-advisory-commit-hygiene.sh` 與 `TestAdvisoryCommitHygieneForbiddenPaths` 阻擋重新追蹤 `jwt.key`／`web/out`。
- **歷史暴露：** 若曾誤將執行時產生的 `jwt.key` 推上遠端，僅從最新 tree 刪除**不能**視為輪替完成；擁有者須依部署紀錄判斷是否需撤銷／重簽，本文件不記錄金鑰內容或指紋。
